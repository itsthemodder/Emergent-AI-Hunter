HunterAI

Fake players that hunt you down. Hunter AI spawns SimulatedPlayer bots that path toward real players, gear up, fight back, and talk trash while doing it — no Java, no server plugin, just @minecraft/server.

what it does

One manager, many hunters

A single HunterManager ticks every hunter once per game tick. Each hunter runs the same loop — scan for a target, decide combat vs. gather vs. wander, then act — driven entirely by scripting, with a GameTest structure used only to anchor the bot into the world.

Targeting isn't purely local either: a hunter that spots someone can "call it in," and allies within 100 blocks will beeline toward that last known position instead of hunting blind.

structure

15 scripts, one job each

No monolith — combat, pathing, gathering, and gear are split into their own files under behaviors/, called from a thin main.js tick loop.

scripts/ ├── main.js # tick loop: reload queue, temp placements, manager.tick() ├── hunterManager.js # spawns/tracks hunters, death & chat barks ├── hunter.js # per-hunter state + decision order ├── settings.js # toggle registry + settings UI form ├── commands.js # /ai:spawn /ai:despawn /ai:clearall /ai:settings ├── data.js # CFG — every tunable number lives here ├── gearUtils.js # armor/weapon tiers, hotbar swaps, snapshot/restore ├── util.js · speech.js · names.js └── behaviors/ ├── combat.js 509 ln # targeting, melee, ranged, crystal PvP ├── pathfinding.js 221 ln # clear-path, bridging, towering ├── survival.js 285 ln # eating, potions, retreat, respawn ├── gather.js 210 ln # crop/log/ore foraging ├── teleport.js 87 ln # catch-up teleport on lost targets └── fishing.js 57 ln # rod pull-in
